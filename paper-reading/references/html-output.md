# HTML 笔记输出规范

## 格式与设计依赖

用户要求将已约定的论文阅读、复习笔记和语料选录交付为 HTML，并调用 `frontend-design`。本规范作为本地定制要求，适用于实际生成笔记的任务。

先读取并使用已安装的 `frontend-design`，环境中没有单独安装时，读取并应用包内完整的 [frontend-design](../vendor/frontend-design/SKILL.md)。遵循其设计、构建和复核流程。包内路径相对当前技能目录解析。用户后续指定的格式和范围优先。

## 输出位置与内容层级

默认在当前研究项目的 `论文笔记/<paper-slug>/reading-note.html` 生成一份可直接打开的笔记。沿用用户指定位置和现有笔记，写入前核对来源和人工改动。标题来自实际论文，文件名取简短可识别名称。篇幅与所选阅读模式匹配。

完整精读按以下内容层级组织，根据论文类型调整章节顺序和适用项。

1. **阅读入口**，论文身份、版本、已读范围、一句话贡献、关键词和目录。
2. **关键词逻辑主线**，场景需求 → 已有做法 → 条件化缺口 → 原因假设 → 方法设计 → 验证 → 收益、代价与边界。连接含义和重要出处可查。
3. **研究过程与详细分析**，作者如何发现问题、为什么选择当前解法、核心机制、原始图表、必要公式及证据审查。理论和综述采用相应结构。
4. **复习笔记**，12 项阅读卡、理解难点与知识联系、重点记忆和按需查阅。
5. **复习问答**，问题先展示，参考答案可逐项展开，答案包含来源位置。
6. **论证与表达语料库**，当次已核对的逻辑条目和精准表达，附中文解释、关键词关系、迁移句式和使用条件。
7. **研究启发与后续验证**，按 deep/extend 范围呈现已约定的启发、计划、迁移条件和复现检查。
8. **来源与范围说明**，论文原文链接、支撑科学判断的参考材料、未读内容和实际验证状态。

这些层级组合成同一阅读页面。相关证据、定义和语料通过稳定锚点交叉引用。速览笔记保留简短逻辑链、必要结论、证据与边界。局部笔记聚焦所请求内容。

## frontend-design 的具体应用

先围绕论文主题和读者目标形成简短设计计划，确定配色、标题与正文的字体角色、内容宽度、导航布局和一个能表达论文特点的视觉元素。将计划落实为 CSS 和页面结构，并在页面生成后复核。默认以长期阅读与复习为目标，优先使用清晰的层级、舒适的行距和有限的强调色。

可以把“关键词逻辑主线”作为页面的主要视觉组织元素。桌面端按论证顺序横向或分组展开，窄屏改为纵向排列。箭头和连接词应表达真实的条件、假设、设计或证据关系。内容使用实际论文材料，教学示例明确标记。

标题、正文、图注和数据有可辨识的字号与字重。字体采用本地可用的中英文字体及合理回退。对关键词、论文事实、作者解释、分析者推断和未验证假设使用一致的文字标记，颜色作为辅助线索。图表与公式保留阅读所需的空间，语料使用适合长文本的段落式排版。

## 页面实现要求

- 使用完整 HTML 文档、UTF-8、与正文一致的 `lang`、viewport、语义化标题、`main` 和目录导航。界面语言与笔记语言一致。
- CSS 内嵌。必要脚本内嵌，优先利用原生锚点与 `details/summary`。复习答案默认折叠，重要结论、局限和范围说明可直接阅读。
- 页面在桌面和窄屏均可读，键盘焦点清晰，控件有明确名称，尊重减少动画设置。长表格、公式和代码局部滚动，正文正常换行。
- 主要内容、图片、样式及必要数学渲染离线可用。展示的原图和裁剪图嵌入为 data URL，保留图注、面板、单位、标注和来源。外部链接用于查阅原文。
- 公式使用离线可用且经过检查的数学渲染方式，或保留清晰的原式裁剪。重要符号和适用条件在正文解释。
- 用户提供的论文文本按文本正确转义，链接目标与资源路径可核对。引用原文、中文释义和分析者提炼在视觉与语义上分别标明。
- 若提供筛选、搜索、复制或展开按钮，每个控件须实际可用。页面在脚本不可用时仍保留核心阅读内容。
- 打印样式保持正文、原图、表格和来源可读，并展开参考答案和必要内容。

## 检查与交付

完成后实际打开最终 HTML，检查至少桌面和窄屏两种宽度。核对标题和目录、锚点、关键词逻辑链、原图完整性、公式、表格、双语语料及问答交互。检查键盘操作、离线资源和打印样式。可用时截图检查遮挡、截断与溢出。

同时核对页面与阅读记录中的关键数字、条件、证据归属及语料 ID。确认所有外部来源主张可回查，累计语料与 HTML 所展示的新增条目一致。最终页面聚焦研究内容，技能作者与方法来源集中记录在 README，页面中的学术引用保持可回查。

工具不可用时，说明未完成的具体检查与已完成验证。最终聊天回复提供实际 HTML 文件链接，简要交代阅读范围、语料累计情况及重要未验证事项。Markdown 草稿、证据 JSON 和渲染中间材料按需要保留为辅助记录，按用户要求提供。
