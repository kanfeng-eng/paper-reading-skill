# 论证与表达语料库

## 收录目标

收集能提升科研推理与写作的真实材料。优先选择逻辑推进清楚、概念边界明确、证据与主张强度匹配、限定条件准确的表达。分析关键词如何通过因果、转折、递进、对比、让步或条件关系构成论证。

精读过程中在对话里共同选录和分析高价值条目。先展示原文与上下文，邀请用户解释其功能或尝试改写，再点评逻辑、措辞和边界，形成可迁移句式。按用户需要先示范或给提示。最终笔记汇总对话成果，候选与已讨论条目分别标记。

## 两类条目

### 论证逻辑

关注应用需求如何引出技术问题、已有进展如何导向条件化缺口、观察如何支持原因假设、假设如何约束方法、实验如何检验机制，以及结果如何导向有限度的结论。

阅读必要的上下文，把论证拆成“前提 → 观察或缺口 → 推断或假设 → 方法或检验 → 结论与边界”。标出关键词、连接关系与被省略的前提。区分作者实际写出的论证和分析者重建。多句或多段的逻辑主要用转述和原文位置记录，摘录最有代表性的短片段。

### 精准表达

关注如何定义研究对象、限定适用条件、公平描述前作、精确说明方法作用、区分相关与因果、表达证据强度、报告收益与代价，以及承认局限。

摘录必要的短语或短句，解释关键动词、限定语和句式如何控制含义。保留原文中的条件、范围、否定与不确定性。结合上下文评价措辞精度和主张的科学支持程度。

## 每条记录的格式

以 `### L0001 条目名称` 记录论证逻辑，以 `### E0001 条目名称` 记录精准表达。ID 在同一累计文件中持续递增并保持稳定。条目采用短段落，字段名称加粗，避免宽表格挤压原文与解释。

- **来源与位置**。论文标题、作者与年份、版本、DOI 或链接或本地路径，以及章节、页码、段落、图表或 source-map ID。位置使用实际核对的定位。
- **原文摘录**。用引用格式保留经核对的原始措辞，注明原文语言。中文释义另列。对断句、连字符、公式符号或 OCR 有疑问时先核对源页面，仍不确定则保留问题状态。
- **上下文与作用**。用简短转述交代前文建立了什么、此处完成什么论证动作、后文如何承接。给出功能标签，如研究缺口、方法动机、证据解释或局限表达。
- **逻辑与关键词**。写明关系链，解释关键术语、连接词、量词、限定语或动词的作用。论证条目展开主要推理，表达条目聚焦措辞及语义边界。
- **值得学习的原因**。具体说明它如何消除歧义、限定主张、衔接证据或推动推理。
- **可迁移句式**。把内容抽象为含 `[场景]`、`[条件]`、`[机制]`、`[证据]` 等槽位的句式或推理骨架，标明“分析者提炼”。中文和原文语言按需要提供。
- **使用条件与证据要求**。说明何时适用，需要什么数据或论证支撑，哪些限定词必须保留，以及改写后主张强度是否发生变化。
- **关联记录**。按需连接阅读卡、D/C/E 证据记录或已有语料条目。证据 ID 与语料 ID 分别标明类型。

原文、释义、逻辑重建和提炼句式分别标记。作者没有写出的连接作为分析者推断处理。外部检索来源遵守适用的摘录额度，用简短引用配合转述保留长论证的结构。多个摘录在同一来源的额度内累计。用户提供的材料按适用规则处理。

## 累计与检索

该工作流包含持续使用的项目语料库。默认累计文件为当前研究项目的 `语料库/论证与表达.md`，已有明确语料文件时沿用原路径。相对位置以本次论文任务的项目目录为准。首次建库可复制包内 [语料库模板](../assets/corpus-template.md)，随后按真实阅读内容追加。

每条记录补充讨论状态和来源，区分 AI 候选、用户解读或改写、导师反馈、讨论修订及待核实项。用户未回应时保持候选状态。累计文件保存经过讨论或明确标记状态的条目，最终 HTML 汇总相同条目、出处和关键词关系。

新增前读取已有条目，按来源标识、版本、位置和摘录内容检查重复。相同材料复用条目 ID，新的学习角度补充到原条目并保留用户修改。不同版本或冲突内容分别标记。实际新增或修订后报告条目数和文件位置，保存失败时交付已完成内容并说明状态。

同一文件内按“论证逻辑”“精准表达”两类组织，用条目标题和功能标签检索。首次收录后更新“尚未收录”的空库说明。库中原文措辞的学习与改写须保留来源。往用户论文迁移时，依其真实问题和证据重新表达，并核对必要引用。

## 输出前核对

- 摘录与源文一致，来源、版本、定位和上下文可核对。
- 条目说明了具体逻辑或表达价值，关键词及其关系清楚。
- 原文中的条件与不确定性保留，分析者提炼有清晰标记。
- 迁移句式附使用条件，逻辑学习与科学结论的可信程度分别交代。
- ID 稳定、重复检查完成、已有人工内容得到保留，报告的保存结果与文件一致。
