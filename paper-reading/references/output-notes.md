# 输出笔记

## 目的与范围

把已核对的论文内容与实际带读对话整理为详细、逻辑连贯、可独立复习的讲义。说明关键词之间的因果、条件、对比和证据关系，保留逐步推导、必要背景、关键追问与修正。

默认完成约定的互动精读与讨论后再生成笔记。AI 备课读完原文与用户读完要分别记录。用户中途要求时生成标注已读与待读范围的阶段笔记，明确要求直接报告时遵循其请求。详细笔记按理解需要展开，不设一至两页的篇幅限制。

笔记以可离线打开的 HTML 文件交付，生成阶段调用 frontend-design 并遵循[HTML 输出规范](html-output.md)。页首先给简短导航与主线，正文充分解释每个关键环节。对话形成的研究启示、行动计划与语料在正文对应位置及汇总区保留出处、推理和讨论状态。

## 综合采用方式

将研究逻辑、分层阅读、知识联系和主动回忆共同用于同一份笔记。

| 方法 | 对输出的具体影响 |
|---|---|
| 研究论证结构 | 用关键词和论证主线组织内容，以 12 项阅读卡保证任务、缺口、假设、方法、证据、代价和局限等信息覆盖。 |
| 分层阅读 | 按阅读深度筛选材料，突出背景、贡献和关键假设，保留疑问及后续想法。实际只读到哪一层，就记录到哪一层。 |
| 理解与知识联系 | 面向未来的自己，用自己的话解释关键关系，留下费力才理解的机制、推导或区别，以及与已知方法的联系和研究启发。 |
| 主动回忆 | 将核心问题、主张和机制转成有上下文的复习问题，保持问题粒度清楚，答案保留来源、适用条件与主张归属。 |

上述内容按理解关系融合。关键词连接研究主线，阅读卡承载事实和定位，理解难点解释主线中的关键跳跃，复习问题检验能否回忆这些关系。具体记忆项和数量根据用户目标与论文内容选择。

## 关键词与逻辑主线

先抓住论文的关键对象和关系，再形成阅读卡。代码检查、复现和实验按当前任务的实际授权与完成状态记录。

选取少量能串起本文贡献的关键词，通常涵盖任务、场景或条件、瓶颈、原因假设、方法机制、验证方式和边界。数量服从论文内容。采用统一术语，首次出现时补充必要的英文原词及通俗解释。详细报告已提供术语表时，笔记保留简短解释或定位。

写出一条带具体关键词的逻辑主线，并在后文用连贯句子展开各环节。

**场景需求** → **已有做法** → **特定条件下的不足** → **原因假设** → **针对性设计** → **验证证据** → **收益、代价与边界**

例如可组织为“在……场景中，需要……。已有方法通过……实现目标，但在……条件下出现……。作者据……提出原因假设，因此采用……改变……环节。……实验支持……，其代价和适用边界为……”。这是写作结构示意，具体机制、数字和条件均从已读论文获取。

区分观察、原因假设、设计动机和验证结论，在相应环节标注证据或推断。证据缺失的连接保留为未知或待验证。理论论文沿问题、假设、关键构造、证明和适用条件组织，综述沿范围、分类依据、证据与未解问题组织。多条贡献主线可以分支，交代它们的依赖或并列关系。

详细输出中的术语表使用“关键词｜自己的解释｜在论文中承担的作用｜证据位置”四列。选择需要解释、且对理解主线有作用的词。正文通过因果、条件、对比、约束和验证关系串联术语，每一关键设计说明它针对的问题，以及支持其作用的证据。

## 选择值得留下的内容

围绕下列问题筛选内容，按论文类型合并条目。用简短、可独立理解的解释回答，重要结论附原文位置。必要时标注“重点记忆”“按需查阅”“待核实”，把精确参数、完整推导和次要结果放入查阅层。

| 内容 | 笔记应帮助读者回答的问题 |
|---|---|
| 论文信息 | 标题、作者、年份、会议或期刊、DOI 或链接，以及实际版本和已读范围。用一句话概括任务与贡献。 |
| 研究任务 | 输入、输出、场景、任务定义与约束是什么？ |
| 核心问题 | 作者要解决什么具体困难，哪些发现线索说明它值得研究？ |
| 已有方法 | 最相关的技术路线是什么，各自解决了什么，又留下什么瓶颈？选择能解释本文动机的少数路线，注明核查范围。 |
| 研究缺口 | 在什么条件下，已有方法出现什么不足？相应证据和问题发现线索在哪里？后续是否解决，按实际核查状态记录。 |
| 核心假设 | 作者如何解释问题成因，为什么认为新设计能起作用？保留推断标签与假设可能被否定的条件。 |
| 方法拆解 | 输入 → 关键操作或模块 → 输出如何流动？各设计对应什么瓶颈？保留必要公式、符号含义和条件，张量 shape 在来源明确且有助理解时记录。 |
| 实验设置 | 数据集、版本、划分、指标、基线、训练和评测的关键配置是什么？记录影响公平比较的差异。理论或综述填写对应假设、证明条件或文献范围。 |
| 关键结果 | 哪些主对比、消融、可视化、证明或其他证据支持主张？结果是否提升、为什么提升、代价是什么、何时失败？代表性数字附指标方向、单位、比较条件和原文位置。 |
| 局限与疑问 | 哪些假设或边界限制适用性？哪些解释未验证？回看哪幅图、公式或参考工作能解决疑问？ |
| 代码状态 | 官方仓库、配置、权重的可用状态，以及本任务实际完成的检查。分别记录已找到链接、已检查实现、已运行和已复现，按证据填写。无法确认时标注未核查，非代码研究说明适用情况。 |
| 可迁移启发 | 与已知课题或知识有什么联系？什么研究思路可以复用，条件是什么？新的应用想法标为分析者提议，已有计划交叉引用对应行动。 |

对关键结论持续区分论文报告、作者解释、分析者推断和待验证想法。笔记中的比较基于实际检查的来源。用户尚未表达的理解变化可以写成“可带走的理解”或复习提示。

## 详细笔记组织

根据实际内容调整下列综合组织方式。

1. **论文信息与一句话概括**，快速定位原文、阅读范围和贡献。
2. **关键词与逻辑主线**，列出少量关键词，以一条具体主线串起需求、已有做法、缺口、假设、解法、证据及边界。解释各连接的含义。
3. **单篇论文阅读卡与详细讲解**，12 项阅读卡提供导航和证据定位。其后按研究问题、发现线索、假设、方法、公式、实验和边界展开，写清每次关键推理与设计取舍。数据流、张量形状、符号与中间步骤根据来源及理解需要说明，阅读卡的简短条目链接到相应详细段落。
4. **理解难点、带读问答与知识联系**，记录对话中实际提出的问题、用户的关键解释、导师的反馈与修正，以及必要例子、反例和推导。按“疑问 → 推理 → 证据 → 修正后的理解 → 条件与边界”整理。用户理解程度据实际作答表述。
5. **重点记忆与按需查阅**，从阅读卡和理解难点中选出最值得记住的关系，补充必要的图表、公式、参数或实现位置及查阅用途。与阅读卡相同的内容通过引用复用。单独展开讲图时使用检查过的图表区域裁剪，保留必要面板与图注。
6. **复习提问与参考答案**，让读者遮住答案后尝试回忆。问题优先检验主线、机制、概念联系和边界。启发和未解问题保留在阅读卡对应项，按需引用。
7. **未来研究启示、下一步计划与论证表达语料**，按对话中实际形成的内容汇总，保留作者建议、AI 提议、用户想法、讨论修订和待核实项的区别。研究计划写清依据、假设、对照、最小验证与失败判据；语料保留原文、逻辑分析、句式、用户改写和适用条件。未讨论的内容明确标记。

显式要求速览或简短笔记时再压缩。默认详细笔记保留完整解释链和重要对话收获，跨章节引用减少重复，关键推理在其所在章节说明清楚。

复习提问通常选取 3–5 个高价值问题，根据阅读深度和实际内容调整。每题集中检查一个清晰关系，并在有价值时加入一道串联全篇的题目。优先覆盖研究问题、解法理由、机制、证据或失效条件。题目写明论文或方法名称，避免脱离背景后无法辨认。

先列问题，再单独列“参考答案”，答案简洁且带原文位置或可核验的证据记录 ID。原文只报告而尚未充分验证的内容，问题和答案都保留“该论文报告”之类归属。未解决的问题保留为待查项。以实际用户作答记录理解情况。

## 输出前核对

- 笔记中的每个关键判断都来自已读材料，重要原文位置可回查，实际阅读范围清楚。
- 核心方法和理由可从笔记中恢复，数字仍附比较条件，适用限制和未知内容保留。
- 关键词有明确含义和论证作用，逻辑连接区分因果假设、条件、对比和证据支持，阅读卡覆盖本模块规定的相关字段。
- 确认阅读深度、自己的解释、重要理解难点或知识联系、重点记忆与复习问题均按实际内容处理。
- 复习问题能从已核对内容回答，答案和问题分开放置。
- 已有图表解释、证据卡和行动计划通过交叉引用复用，便于复习的简要结论留在笔记中。
- 保存时沿用现有报告和证据，不额外生成用户未要求的卡包、日程或外部同步。
- HTML 完成 frontend-design 设计、浏览器阅读检查、离线资源和复习交互检查，最终交付链接指向实际生成的文件。未完成的检查按实际状态说明。

## 汇总前检查

核对约定范围是否已经带读，讨论记录是否真实。研究启示、计划和语料应能指向对话中的提出、分析与修订，未回应的建议保持草案状态。核对笔记中的所有图表都是对应区域的裁剪或原始单图，正文说明逻辑与证据，不能用完整页面替代图表。
